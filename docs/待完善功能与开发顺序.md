## P1 · 团队成员和负责人闭环

### 成员管理

- 显示团队成员、角色、项目成员和负责人资料。
- 团队管理员能把已注册用户加入团队，再授权其进入指定项目；允许移除项目成员并处理其已分配任务（清空负责人，不删除任务）。
- 普通成员不能增加/移除团队或项目成员；由 RLS 拒绝越权请求。
- 处理重试和并发：重复加入应幂等；管理员移除成员时若成员仍有任务，任务继续保留且变为未分配。

### 邀请/加入方式（实现前确定）

- 直接读取 `auth.users` 不是浏览器功能。不能在前端使用 service role 查询邮箱或调用 Admin API。
- 正式邮件邀请需要受信任 Edge Function、密钥管理和 SMTP；SMTP 当前暂缓。
- SMTP 暂缓期间，可先实现管理员添加“已注册用户”的受控方案，或另行设计限时邀请码/加入申请；不能仅靠可猜测的团队 ID 作为加入凭证。
- 需要定义待接受/已接受/过期/撤销状态、重复邀请、错误邮箱、用户不在团队、项目权限继承和邀请人权限。

### 负责人姓名

- 用户本人通过资料设置维护 `profiles.display_name`；显示名只存一份，任务继续关联 `assignee_user_id`。
- 项目成员下拉框只列出已加入该项目且可读取资料的用户；可空表示未分配。
- 新成员尚未填写资料时显示“未设置姓名”，提供补资料入口；名字不能替代身份授权。
