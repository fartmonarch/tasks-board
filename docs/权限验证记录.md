# 权限验证记录

## 2026-10-04 · 角色基础与任务删除权限

来源：维护者在本对话反馈的手动页面测试。本次进度整理没有重新运行这些测试，也没有直接查询远程数据库。

测试身份：A 为已手动登记的系统管理员；B 为创建测试项目的 owner；C 为加入该项目的 member。A 未加入 B 的项目。

| 场景 | 预期结果 | 维护者实际结果 |
| --- | --- | --- |
| B 创建项目和任务；C 加入并创建自己的任务 | 创建、加入和任务创建正常 | 通过 |
| C 删除自己的任务，再尝试删除 B 的任务 | 本人任务可删除；B 的任务保留 | 通过 |
| B 删除 C 创建的任务 | owner 可删除本项目成员任务 | 通过 |
| A 直接打开 B 复制的看板地址 | 无需加入即可读取、创建、修改和删除任务 | 通过 |

上述结果作为角色基础阶段的已通过基线，后续无需为了更新进度而重复整套手动测试。若修改相关 RLS、授权函数、任务删除请求或成员关系，则复核受影响场景；邀请阶段会修改成员加入和项目读取规则，需补验新加入后的访问及管理员访问。

## 已知问题与排期

| 问题 | 当前判断 | 后续任务 |
| --- | --- | --- |
| 普通成员仍能看到他人任务的删除按钮 | 数据库已限制删除，前端尚未读取角色和任务创建者来控制按钮 | 邀请之后单独做任务权限界面；同时处理删除零行不能误报成功 |
| 管理员没有全部项目列表入口 | 数据库跨项目权限已存在；当前“我的项目”仍按成员关系查询 | 单独增加管理员“全部项目”入口；保留“我的项目”的本人创建/加入语义 |
| 要手动刷新才能看到任务变化 | 维护者已反馈。代码有本人 mutation 后的列表缓存失效，没有跨账号同步；本轮未复现并区分本人操作、他人操作和详情缓存 | 协作刷新任务先定位场景，再实现可见页面定时刷新、手动刷新及返回页面刷新；初步建议约 10 秒，不预先要求 Realtime |

任务权限界面的实现需要同时读取当前用户身份、项目角色和任务 `created_by`；判断只用于操作展示，数据库仍是最终授权。

## 尚未覆盖的线上验收

## 2026-10-04 · 仅邀请加入与关闭公开发现

本轮新增源码和 migration，没有应用远程或发布前端。线上仍为前述角色权限和公开加入状态，没有重复整套任务删除页面测试。

- **实际数据库运行**：隔离 PostgreSQL 17.6 重放历史迁移和新 migration，20 项检查全部通过；包括现有业务行完全保留、GRANT/RLS/RPC 权限、owner/admin 生成、有效/过期/伪造/重复兑换、数据库哈希不能兑换、已有成员不消费、直接自行加入拒绝、普通未加入用户隔离及管理员未加入访问。
