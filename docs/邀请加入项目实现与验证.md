## 本轮范围与行为

- owner 在项目看板点击“邀请成员”，生成并复制一次性链接；系统管理员即使未加入项目，也可按既有全局权限生成邀请。普通成员没有邀请入口，数据库同时拒绝生成。
- 每个链接固定 24 小时有效，仅允许一个新成员加入。再次生成会得到另一条独立邀请；本轮没有邀请列表、撤销面板、有效期设置或邮件发送。
- 链接形式为 `/invite#token=随机凭证`，不包含项目 ID。URL fragment 不发送给站点服务器；应用不记录令牌，不放进 Query 的查询键、持久化存储或错误消息。原始链接只在当前页面内存、地址栏及用户主动复制的剪贴板中使用。
- 未登录访问由现有 `AuthGate` 显示登录页，保留路径和 fragment。登录成功后显示当前账号；点击“接受邀请并进入项目”后兑换、刷新“我的项目”缓存并进入看板。注册需邮箱验证时，完成验证后返回原邀请页登录，或重新打开原邀请链接。
- 已有成员持有可识别的链接时直接进入，不消费名额；即使该邀请已过期或已被消费，也不影响其原有成员权限。伪造凭证始终拒绝。新用户遇到过期、伪造、已消费邀请得到统一错误提示。
- 移除“可加入的项目”和旧加入 API。普通未加入用户不能通过列表或项目 ID 读取其他项目，不能直接写 `project_members` 自行加入。
- “我的项目”继续只查当前用户的成员关系，管理员也遵循这一列表语义。标签读取当前 `project_members.role`，owner 显示 `(owner)`；管理员全部项目入口仍留给后续任务。

## 数据库变化

新文件：`supabase/migrations/20261003160939_invite_only_project_membership.sql`，由 Supabase CLI `migration new invite_only_project_membership` 生成。没有修改已经应用的迁移。

1. 新建 `private.project_invitations`：项目、生成者、创建/到期时间、消费时间/使用者及 32 字节哈希。固定有效期约束；项目外键只在原项目被删除时级联删除该项目邀请。没有变更现有项目、成员、任务、评论或管理员记录。
2. 令牌由 `extensions.gen_random_bytes(32)` 产生，提供 256 位随机性。生成 RPC 仅当次返回原始令牌。浏览器用 Web Crypto 计算 `proof = hex(SHA-256(token))`，兑换 RPC 只接收 proof；数据库存储 `SHA-256(proof)`。第二层哈希保证数据库保存的值不能直接拿来兑换，且兑换请求与数据库错误不携带原始令牌。
3. 邀请表位于未暴露的 private schema，启用 RLS、无直接访问策略，撤销 PUBLIC/anon/authenticated/service_role 表权限。哈希和消费状态没有客户端列表查询入口。
4. `projects` SELECT 改为成员/系统管理员可读，撤销公开发现策略。撤销客户端项目和成员 INSERT 的表级及列级 GRANT，删除相应 INSERT policies，防止自行加入或留下只有项目、没有 owner 的记录。
5. 保留 `public.create_project(text)` 签名，改为 invoker 包装私有 definer 函数；私有函数校验 `auth.uid()`，事务内创建项目和当前用户 owner 关系。客户端不能指定创建者、成员身份或角色。
6. 新增 `can_invite_to_project(uuid)`、`create_project_invitation(uuid)`、`redeem_project_invitation(text)` RPC。写入函数封装在 private schema，固定空 search_path、限定对象 schema，PUBLIC/anon/service_role 无执行权限，仅 authenticated 可以执行。浏览器只使用已有 publishable key 和登录 JWT。
7. 兑换先按哈希 `FOR UPDATE` 锁定邀请，再检查成员关系、有效期和消费状态，插入当前用户 member 并记录消费。同一邀请的并发请求被串行处理；失败会回滚成员和消费。不同邀请同时加入同一用户时，成员主键冲突只允许一条成员关系，未新增成员的邀请不消费。锁等待后使用实际时钟复查到期时间。

任务删除 RLS 和系统管理员登记方式没有改变。普通成员仍只可删除本人任务，owner/admin 按原有范围管理；本轮只复核新增成员及管理员访问边界。
