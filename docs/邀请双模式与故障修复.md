## 两种邀请

| 模式 | 有效期 | 新成员使用规则 |
| --- | --- | --- |
| `single`，默认单人邀请 | 固定 24 小时 | 第一位新成员加入后消费，其他新成员不能再用 |
| `group`，多人邀请 | 固定 1 小时 | 到期前可供多位新成员加入，不限制人数、不记录单次消费 |

两种模式均只允许 owner/系统管理员生成，新加入者为 member。已加入者打开可识别的链接只进入项目，不新增成员，也不消费邀请；到期不影响其已有项目访问权限。普通成员仍不能生成邀请，普通未加入用户仍需有效邀请才能加入。

邀请弹窗新增模式选择，生成后锁定当前模式，关闭并重新打开可生成另一种链接。复制及失败时手动复制逻辑保留。原始凭证继续使用 256 位随机值和 fragment，数据库继续只保存双 SHA-256 哈希；没有邮件、可配置有效期或邀请管理面板。

看板标题下新增“返回我的项目”按钮，用 React Router 返回现有 `/projects`。仓库实际项目列表路由是复数 `/projects`，不是 `/project`，本轮没有新增别名路由。

## 新 migration 与兼容性

`supabase/migrations/20261003163828_support_project_invitation_modes.sql` 由 Supabase CLI 创建，没有修改上一轮 migration：

- 邀请表增加 `mode`，既有邀请默认回填 `single`；旧有效期、消费记录、项目及成员关系全部保留。
- 有效期约束按模式固定为 24 小时/1 小时；多人邀请禁止写入单人消费状态。
- 新增独立 `create_project_invitation_with_mode(uuid,text)` RPC，数据库验证模式；不通过同名重载或客户端指定任意时长。
- 保留旧 `create_project_invitation(uuid)` 接口并委托单人模式，兼容已发布的上一版前端。
- 兑换继续锁定邀请，在事务中校验并加入；单人模式消费，多人模式可重复使用；锁等待后复核过期时间。
- private 写入函数仍校验身份，固定空 search_path；新 public RPC 是 invoker 包装，PUBLIC/anon/service_role 无执行权限。邀请表保持 RLS 和客户端无直接表权限。
- migration 提交后通知 PostgREST 重载 schema，避免函数缓存滞后。
