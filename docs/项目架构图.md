## 阅读重点：服务端能力在哪里

本项目的浏览器端通过 `supabase-js` 直接调用 Supabase，没有单独部署的 Express 应用服务层。服务端能力分布在 Supabase Auth、Data API 和 PostgreSQL：

1. **身份与会话**：Supabase Auth 处理注册、密码登录和 JWT session；React 的会话门禁恢复会话并控制已登录页面入口。
2. **请求入口**：页面领域代码使用 Supabase Data API 查询表或调用 RPC。浏览器带着用户会话发请求，SDK 并不绕过数据库授权。
3. **授权边界**：PostgreSQL 的 `GRANT` 决定角色能否访问表或列，RLS 决定该角色能访问哪些行；前端隐藏按钮只负责呈现，不是权限保障。
4. **事务和业务规则**：数据库函数/RPC 可在数据库事务中完成需要原子执行的操作。邀请兑换在事务内校验凭证并加入成员；令牌哈希保存在不向客户端开放的 `private` schema。
5. **持久化**：PostgreSQL 表、约束、索引和外键保存项目、成员、任务与评论；任务排序由 invoker RPC 写入并继续受现有授权规则约束。

## 建议的源码阅读顺序

- 应用入口与路由：[src/main.tsx](../src/main.tsx)、[src/app/App.tsx](../src/app/App.tsx)
- 登录状态：[AuthGate.tsx](../src/features/auth/AuthGate.tsx)、[AuthPage.tsx](../src/features/auth/AuthPage.tsx)
- Supabase SDK：[supabase.ts](../src/lib/supabase.ts)
- 浏览器数据调用：[projectApi.ts](../src/features/projects/api/projectApi.ts)、[projectInvitationApi.ts](../src/features/projects/api/projectInvitationApi.ts)、[taskApi.ts](../src/features/tasks/api/taskApi.ts)
- 数据库规则和函数：[supabase/migrations](../supabase/migrations)

学习时可以沿着图中的一条写入链追踪：页面操作 → 对应 feature API → Supabase Data API/RPC → PostgreSQL 的 GRANT/RLS/函数 → 表与事务。遇到权限拒绝时，从数据库授权和策略入手；遇到需要原子完成的多步写入时，观察迁移中的事务函数。
